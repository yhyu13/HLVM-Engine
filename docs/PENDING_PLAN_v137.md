# Pending Plan v137
- task: Add `setBindingOffsets(0,0,0,0)` to the manually-built UAV `BindingLayoutDesc` in FGIPass.cpp to fix descriptor-slot double-add bug (binding slot 384+384=768 instead of 384)
- source: docs/PIPELINE_HEALTH_2026-07-31_tick246.md §1 (NEW file-only verifiable finding) + docs/DIAGNOSTIC_2026-07-30-v24.md §"What mode 6 reveals" (mode 6 all-zero dump = UAV write not landing)
- approach: At `Engine/Source/Runtime/Private/Renderer/GI/FGIPass.cpp:301-310`, the UAV `BindingLayoutDesc` is built manually without calling `setBindingOffsets()`. The default `VulkanBindingOffsets` has `unorderedAccess=384`. The items are placed at `URegShift + N = 384 + N`. nvrhi's `BindingLayout` ctor (vulkan-resource-bindings.cpp:100) computes `bindingLocation = registerOffset + binding.slot = 384 + 384 = 768`. The shader expects `Binding=384`. **Mismatch.** The descriptor set is allocated with bindings at slot 768, but the shader reads from slot 384. Writes are silently dropped. Add an explicit `setBindingOffsets(0,0,0,0)` call BEFORE the items are added. The fix matches the FReSTIRPass precedent (FReSTIRPass.cpp:162, 187, 208) which already calls `setBindingOffsets(0,0,0,0)` on all three of its layouts.
