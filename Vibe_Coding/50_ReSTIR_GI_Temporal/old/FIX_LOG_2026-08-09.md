## Phase 1 — ReBLUR denoiser was a pass-through (FIXED)

### Symptom (baseline 20:23)

`denoised` was effectively identical to `spatial`: high-frequency (HF) energy
dropped only 0–2%, mean absolute error (MAE) < 1/255. The denoiser never
denoised.

| Metric (RGB) | gi_raw | spatial | denoised (before) |
|---|---|---|---|
| HF std (pixel − 3×3 mean) | 6.16 / 6.85 / 8.29 | 8.27 / 7.17 / 8.22 | 8.13 / 7.01 / 7.45 |
| max float | — | 1.6238 | 1.2775 |

### Root causes (three, stacked)

1. **`SpatialAlpha` was never sent to the shader.** `FReBLURPass::Dispatch`
   read `Constants.SpatialAlpha` (0, because the test memsets the constants),
   not `BlurParams.SpatialAlpha` (0.6). The shader's
   `lerp(temporal, blurred, alpha)` therefore always returned `temporal` —
   the blur result was discarded. `FReBLURPass.cpp:216`.
2. **GBuffer MRTs were never cleared.** Un-rasterized sky texels kept
   uninitialized GPU memory (NaN bit patterns in the RGBA32F normal texture).
   ReBLUR's neighbor gather pulled those NaN values into the weights
   (`pow(saturate(dot(NaN, …)), w) = NaN`), so `weightSum`/`sum` became NaN,
   the `weightSum > 0.001` guard failed, and every pixel fell back to the
   temporal (≈ input) value. `TestReSTIR_GI_Temporal.cpp::RenderGBuffer`.
3. **View-space plane rejection reconstructed garbage.** `ReconstructViewPos`
   fed the *linear-depth* texture into an NDC-z projection, producing
   nonsense positions and near-zero neighbor weights. `ReBLUR_cs.hlsl`.

### Changes

- `FReBLURPass.cpp`: `SpatialAlpha` now comes from `BlurParams`.
- `TestReSTIR_GI_Temporal.cpp::RenderGBuffer`: clears all 4 MRTs each frame
  before the draws (worldpos=0, normal=(0,0,0,1), material=0, depth=0).
- `ReBLUR_cs.hlsl`: removed the broken view-space reconstruction; bilateral
  weight is now `exp(-(|Δd| / max(d, ε)) * PlaneWeight)` (relative-depth,
  perspective-correct); neighbor loop skips non-finite / zero-depth samples;
  normal weight uses `pow(saturate(dot), w)`; result guard checks finite sums.
- `FReBLURPass.h`: tuned defaults — BlurRadius 8, NormalWeight 2,
  PlaneWeight 12 (relative), SpatialAlpha 1.0.

### Proof (run 20:38, dumps in `evidence/phase1_reblur/`)

| Metric (RGB) | spatial | denoised (after) | Δ |
|---|---|---|---|
| HF std | 8.27 / 7.17 / 8.22 | 7.87 / 6.79 / 7.05 | −4.8% / −5.3% / −14.2% |
| MAE denoised−spatial | — | 0.90 / 0.72 / 1.30 | >0 (real change) |
| NaN pixels | 0 | **0** | pass-through mechanism eliminated |

G and B channels now denoise *below* the raw `gi_raw` noise floor; R is close
(residual is edge structure the bilateral intentionally preserves, plus
grazing-angle surfaces the depth term still rejects).

Validator: 4/4 PASS on the Phase-1 dump set.

**Screenshots:** `evidence/phase1_reblur/20260809_203834_spatial_frame8.png`
(input), `..._denoised_frame8.png` (output), `..._display_frame8.png`
(what the swapchain shows).

## Phase 2 — Validator blind spots (FIXED)

### Symptom (baseline)

`validate_restir_gi.py` ran only 4 checks on display/GBuffer/alpha. It never
inspected `spatial`/`denoised`, so a run with ReSTIR skipped
(`HLVM_RGI_BYPASS=1`) or a dead ReSTIR chain still passed 4/4 — the exact
hole that let the 17:30 Aug-08 bypass run masquerade as a healthy run.

### Root cause

The validator was designed around "is there a non-black, structured image?"
but not "did the ReSTIR+denoise stages actually execute and change the
signal?".

### Changes (`validate_restir_gi.py`)

1. **check 5 — `check_restir_alive`**: `spatial`/`denoised` mean must be > 5.
   Black ReSTIR channels → FAIL "ReSTIR dead or HLVM_RGI_BYPASS run".
2. **check 6 — `check_denoise_effective`**: `denoised` must differ from
   `spatial` (MAE > 0.5) **and** have lower high-frequency energy (HF ratio
   < 0.99) — i.e. ReBLUR really blurred. Catches the Phase-1 pass-through.
3. Both checks are skipped when `HLVM_VALIDATE_ALLOW_BYPASS=1` (deliberate
   bypass runs validate only the GI/display chain).

### Proof

| Scenario | Result | Screenshot |
|---|---|---|
| Full pipeline (run 20:40) | **6/6 PASS** (MAE 0.97, HF 7.74→7.17) | `evidence/phase2_validator/20260809_204008_*` |
| Bypass run (HLVM_RGI_BYPASS=1) | **4/6 FAIL, exit 1** — caught "ReSTIR dead or bypass" + MAE 0.00 | validator stdout in fix-log session |
| Bypass acknowledged | 6/6 PASS with checks 5–6 skipped | `HLVM_VALIDATE_ALLOW_BYPASS=1` |

The validator can no longer certify a run whose ReSTIR stages never ran.

## Phase 3 — 56% black display (FIXED)

### Symptom (baseline)

56% of the display was pure black: the camera sees sky through Sponza's open
roof, but RayGen early-returned `(0,0,0,1)` for pixels without GBuffer
geometry, and ReBLUR zeroed those pixels again with its `depth == 0` early-out.

### Root cause

No background/environment term existed on the primary path. The miss shader
already had `SampleSky()` for GI bounces, but primary sky pixels never traced
a ray — they were hardcoded black in two places.

### Changes

- `TestReSTIR_GI_Temporal_Data/GIPathTracing.hlsl` (the copy the ShaderMake
  build actually compiles): the no-geometry branch now unprojects the primary
  ray through the pixel (GLM RH-ZO diagonal unprojection + `mul(vec, view)`
  world rotation) and writes `SampleSky(primaryRayDir)`.
- `ReBLUR_cs.hlsl`: `depth == 0` pixels now pass the current radiance (the
  sky color) through instead of writing black, so the swapchain shows the sky.
- `validate_restir_gi.py`: display-std threshold 30 → 20. The sky fills 56%
  of the frame with a fairly uniform blue, which lowered the frame std to
  ~26; 20 still rejects the uniform-gray baseline (16.28) this check was
  built to catch.

## Phase 4 — ReSTIR spatial resolve was a pass-through (FIXED)

### Symptom (baseline)

`spatial` was effectively `gi_raw` re-issued: the resolve wrote
`selectedRadiance * W` and, with W == 1 for homogeneous radiance, that is the
single center sample — no neighbor contribution was visible in the output
(spatial mean == gi_raw mean, max identical, only 0.1% of pixels moved).

### Root cause

The spatial shader performed unbiased reservoir *selection* (correct in
isolation) but never *combined* the accepted neighbors — and with identical
radiance everywhere the selection is a no-op. The absolute-depth rejection
(`|Δd| > 0.05`) also rejected far surfaces, so few neighbors were accepted at
all.

### Changes (`ReSTIR_Spatial_cs.hlsl`)

1. **Weighted-average resolve**: accumulate `w_i = target_i * W_i * M_i`
   contributions from the center and all accepted neighbors and output
   `Σ(w_i · r_i) / Σ(w_i)`. Neighboring reservoirs now visibly contribute.
2. **Relative-depth rejection**: `|Δd| / max(d, ε) > DepthThreshold` instead
   of absolute, so far surfaces (large absolute deltas, small relative) are
   accepted — matching the Phase-1 ReBLUR fix.

### Proof (run 20:45, dumps in `evidence/phase4_spatial/`)

| Metric (RGB) | gi_raw | spatial (after) | denoised (after) |
|---|---|---|---|
| HF std | 5.89 / 6.69 / 8.51 | 6.45 / **5.59** / **6.15** | 6.34 / **5.31** / **5.73** |
| MAE vs gi_raw | — | 59.9 / 45.6 / 41.5 | — |
| MAE denoised vs spatial | — | — | 0.60 / 0.66 / 0.86 |

Spatial now carries genuine reuse: G/B high-frequency energy drops below the
raw GI input, per-pixel MAE vs gi_raw is large, and the float mean is
preserved (an average, not a brightness shift — the PNG mean difference is a
dump-normalization artifact for gi_raw only). The display stays 0% black.

Validator: 6/6 PASS.

**Note:** this resolve is the biased weighted-average form (denoising-ish),
traded against the unbiased `selected·W` estimator. The unbiased form remains
available for a later correctness pass; the reservoir representation (no ray
direction/Jacobian) is still the architectural limit documented in
`deepseek/PLAN.md`.

**Screenshots:** `evidence/phase4_spatial/20260809_204517_display_frame8.png`,
`..._spatial_frame8.png` (reuse output), `..._gi_raw_frame8.png` (input).

## Round 3 — GBuffer had no depth occlusion ("inside-out mesh" look) — 2026-08-10

### Symptom

User review of the screenshots: "it is like Sponza from inside out mesh".
The display showed a mosaic of interior surfaces showing through the facade —
walls visible through walls, back faces mixed with front faces.

### Root cause

`TestReSTIR_GI_Temporal.cpp` created a D32 depth texture (`GBufferDepth`) but
**never attached it to the GBuffer framebuffer**, and the GBuffer pipeline had
`setDepthTestEnable(false)` / `setDepthWriteEnable(false)`. With 24
overlapping Sponza meshes and no occlusion, every fragment wrote the GBuffer
and the last-drawn mesh won per pixel — a per-pixel patchwork of front and
back/interior surfaces. The camera/scene framing itself was fine (camera at
(0,6,24) outside the ±6 m structure, FOV 75°).

### Fix (`TestReSTIR_GI_Temporal.cpp`)

1. D32 depth texture desc corrected (isRenderTarget, DepthWrite initial state).
2. Framebuffer: `FBDesc.setDepthAttachment(GBufferDepth)`.
3. Pipeline: `setDepthTestEnable(true)`, `setDepthWriteEnable(true)`,
   `setDepthFunc(ComparisonFunc::Less)`.
4. RenderGBuffer clears depth to 1.0 per frame.

### Proof

- Before/after ASCII comparison embedded in `SCREENSHOTS_2026-08-10.md`: the
  `%%` interior patches through the facade are gone; the display is one
  coherent facade with sky top, columns at the edges, floor at the bottom.
- GBuffer depth float stats changed: max 40.4 → 26.0, mean 3.36 → 2.57
  (nearest surfaces now win).
- Display mean changed 0.728/0.717/0.699 → 0.751/0.755/0.764 (correct occlusion
  changes what is lit).
- Validator 6/6 PASS on the depth-fixed frame-32 set.

Screenshots in `evidence/screenshots/` updated to the depth-fixed run.

## Round 7 — "Window shows nothing" investigation (2026-08-10)

Symptom: running the binary shows nothing (no window / black window).

### Findings (verified, not guessed)

1. **The render is correct.** The headless dump (`display_frame8.png`) is
   non-black (mean ≈ 120, 0% black), and a new env-gated swapchain readback
   (`HLVM_DUMP_SWAPCHAIN=1`) proves the presented back-buffer contains the
   render: mean **(182, 186, 193)** vs the dump (181, 185, 192) — exact match.
2. **The window is hidden by default.** `GLFW3VulkanWindow.cpp` creates the
   window with `GLFW_VISIBLE=FALSE` (headless test design). Running the binary
   plain → no window at all, by design.
3. **With `HLVM_SHOW_WINDOW=1` the window appears on top and focused**
   (`_NET_WM_STATE_ABOVE, _NET_WM_STATE_FOCUSED`, top of the client stack) —
   but the compositor still displays **pure black**.
4. **`vkQueuePresentKHR` succeeds** (no validation errors, `Present()` returns
   true every frame, present mode is FIFO) — yet the screen pixels stay black.

### Conclusion

The present path is correct on the renderer side (blit → swapchain image →
present), but the **X11 compositor in this display session never shows the
Vulkan surface content** — an environment/driver compositing limitation, not a
pipeline bug. The dumps (GPU readbacks of the exact rendered textures) are the
authoritative screenshots; the live window cannot be captured in this session.

### Changes kept

- `HLVM_DUMP_SWAPCHAIN=1` diagnostic: reads back the swapchain back-buffer and
  logs its mean (proves what would be presented).
- Visible-window mode (`HLVM_SHOW_WINDOW=1`) now also periodically
  `glfwRestoreWindow`/`glfwFocusWindow` so the window stays on top when other
  windows (e.g. the IDE) are maximized.

**To see the render:** `HLVM_DUMP_RGI=1 ./TestReSTIR_GI_Temporal` → PNGs in
`TestReSTIR_GI_Temporal_Data/dumps/` (and `evidence/` docs). For a live window
on a normal desktop, `HLVM_SHOW_WINDOW=1` should work — the swapchain content

## Round 10 — "Failed to extract shader library" crash (2026-08-11)

Symptom: `FGIPass::Initialize` fails with `Failed to extract shader library
from GIPathTracing.sblob` → the test aborts at startup. Recurred twice.

Root cause: `ShaderMake.cfg` line 1 carried
`GIPathTracing.hlsl -T lib -D HLVM_RGI_DEBUG_VIS` (added deliberately by the
v162 debug-plan workflow at 20:45). Compiling with that define makes the
`.sblob` contain only the `HLVM_RGI_DEBUG_VIS=1` permutation entry — but
`FindPermutationInBlob(..., nullptr, 0, ...)` (no macros) only matches an
entry with an EMPTY permutation string → no match → init failure.

Fixes (both):
1. **Restored the production cfg** — `-D HLVM_RGI_DEBUG_VIS` removed from
   `ShaderMake.cfg`; the blob again has the default (no-macro) permutation and
   the debug sentinels stay compiled out (Round 9 gating intact).
2. **Hardened the loader** — `ShaderMake::FindPermutationInBlob` now falls
   back to the first available permutation when no specific permutation was
   requested and the exact match is absent. The v162 debug workflow
   (add `-D`, rebuild, run) no longer crashes the test — verified: with the
   define in the cfg the run completes; with it out, the default permutation
   is used and the sentinels stay off.

Also kept from Round 9.5: the resolve pass no longer skips half-res texels on
`alpha <= 0` (alpha is the real first-hit distance; sky-escaped rays have
hitT=0) — this had darkened the path-traced image ~3.5× once the sentinel was
gated out.

Verified: production cfg → exit 0, no extraction/VUID errors, gi_raw mean
0.393/0.413/0.469, validator **6/6**, M=2.88.
