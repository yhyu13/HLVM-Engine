## Phase 1 — Reservoir sample model + RIS candidate generation (FIXED)

### Symptom

The "ReSTIR" pipeline was a path tracer whose radiance was post-processed by
ReSTIR-flavored passes: the reservoir held `{radiance, hitT, M=1, W=1}`, the
sample had no BSDF pdf, no second-path-vertex state, and direct lighting was
inside the reused radiance. That is not the ReSTIR algorithm (ZetaRay
`ReSTIR_GI/RIS_InitialCandidates`).

### Root cause

Three conceptual gaps vs ZetaRay:
1. The primary ray used `sampleRoughnessLobe` (cosine + glossy lerp) with NO
   pdf — and `throughput *= albedo` is only exact for cosine sampling of a
   Lambert surface, so the bounce radiance Lo was biased.
2. The reservoir stored the full pixel radiance (direct + ambient + indirect)
   instead of the indirect radiance Lo at the second path vertex x2, so
   reuse merged pixel-level estimates, not path-space samples.
3. No `w_sum`, `target_z`, `W=1/pdf`, or sample vertex (pos/normal/ID) was
   carried, so the temporal/spatial passes could not compute the ReSTIR
   weights (m_curr/m_prev/pairwise MIS) at all.

### Changes

- `GIPathTracing.hlsl` (ReSTIR copy): cosine-weighted BSDF sampling with
  **pdf = cos/pi**; payload carries x2 normal + packed ID (80 B, FGIPass
  maxPayloadSize 64→80); outputs split:
  `Output = float4(Lo, hitT)`, `OutputDirection = float4(x2Pos, asfloat(ID))`,
  `SampleInfo(u3) = float4(x2Normal, pdf)`,
  `DirectTexture(u4) = primaryDirect + primaryAmbient [+ sky on primary miss]`.
  Sky pixels: invalid reservoir + sky in u4.
- Reservoir: 3 half-res RGBA32F textures (ZetaRay layout) — A = pos+ID,
  B = Lo+M, C = w_sum+W+OctEncode(x2Normal) — across FReSTIRPass, the test,
  and the Generate/Temporal/Spatial shaders.
- `ReSTIR_Generate_cs.hlsl`: RIS packaging — `f = albedo·max(NdotL,0)/π`,
  `target = Lo·f`, `w_sum = targetLum/pdf`, `W = 1/pdf`, `M = 1`.
- `GIAccumulate_cs.hlsl` (ReSTIR copy): display = ReSTIR indirect + u4
  (resolved to FullResDirect); `FGIPass` gains u3/u4 with 1x1 dummies for
  the other tests.

### Proof

Zero VUIDs/validation errors; `gi_raw` is now Lo (indirect) with
`DirectTexture` carrying the primary sun+ambient; display 100% non-black.

## Phase 2 — Temporal resampling: pairwise MIS (FIXED)

### Symptom

The old temporal pass used a plain weighted merge
(`w = target·W·M`, `W = sum/(M·targetSel)`) with same-frame depth/normal
validation — no Jacobian, no balance heuristic, no M accumulation under the
turntable.

### Root cause

1. No `JacobianReconnectionShift`, no `m_curr`/`m_prev` pairwise-MIS terms
   (ZetaRay `TemporalResample1/2`).
2. The "prev" depth/normal were SAME-frame aliases (`PrevDepth =
   LinearDepth`), so under the turntable the reprojected pixel's current-frame
   surface was a different surface → every candidate was rejected and M never
   accumulated.
3. History positions were stored in the previous frame's world space but the
   scene rotates; without rotating them into current coordinates the reuse
   geometry was inconsistent.

### Changes

- `ReSTIR_Temporal_cs.hlsl`: full port of ZetaRay `FindTemporalCandidate<2>`
  (plane heuristic, normal similarity, roughness similarity), `TemporalResample1`
  and `TemporalResample2` (m_curr scaling of `w_sum`, per-candidate m_prev
  balance heuristic, reservoir streaming), `JacobianReconnectionShift`, and
  `W = w_sum/targetLum(selected)` with `M = M_curr + Σ M_prev`.
- True previous-frame GBuffer chain in the test (`PrevGBufferWorldPos/Normal/
  Material/PrevLinearDepth`) copied at END of frame (`CopyGBufferToPrev`), and
  the temporal pass reads prev surfaces at the reprojected pixels.
- History reservoir positions rotated into current-frame coordinates with
  `R_y(SceneYaw - PrevSceneYaw)`.

### Proof

Static scene (HLVM_RGI_SCENE_YAW=90): **reservoir M mean=7.71, max=16.0**
(previously 1.0) — the full 16-frame temporal chain accumulates. Rotating
turntable: M max=7.0 (limited by ~20°/frame in the Debug build; reuse is
exact at realistic speeds).

## Phase 3 — Spatial resampling: pairwise MIS (FIXED)

### Symptom

The old spatial pass was a biased 3x3 weighted-average resolve, not a
reservoir merge.

### Root cause

No `PairwiseMIS` (Compute_m_i / Update_m_c / Stream / End) and no Hammersley
neighborhood sampling with the plane heuristic.

### Changes

`ReSTIR_Spatial_cs.hlsl`: full port of ZetaRay `SpatialResample`/`PairwiseMIS`
— per-pixel rotated Hammersley offsets, plane heuristic, normal similarity,
`m_i`/`m_c` balance terms with Jacobian, final
`W = w_sum/(targetLum·(1+k))`, output `target_z · W`.

### Proof

Static scene: spatial grayscale err dropped to 0.091 (from 0.18); ReBLUR
output matches the spatial mean with lower std; validator 4/4 PASS.

## Phase 4 — Segment visibility + outlier suppression (FIXED, 2026-08-22)

### Symptom

Temporal/spatial reuse merged reservoirs without testing whether the sample
vertex was actually visible from the current pixel — light leaks through thin
geometry were possible (ZetaRay always tests `Visibility_Segment`).

### Root cause

The compute passes had no acceleration structure bound and no ray-query
support, so the reuse weights (`target_curr`, `m_i`, `m_c`) ignored occlusion.

### Changes

- `VK_KHR_ray_query` in the compute passes: `RayQuery<ACCEPT_FIRST_HIT_AND_END_SEARCH
  | SKIP_CLOSEST_HIT_SHADER | FORCE_OPAQUE>` port of ZetaRay `Visibility_Segment`
  — a hit on the sample's OWN triangle (packed instance+primitive ID) is not an
  occluder; anything else returns occluded.
- FReSTIRPass binds the TLAS to the temporal (t16) and spatial (t8) layouts;
  `checked_cast` safety means every consumer supplies a real TLAS —
  TestReSTIR_GI_Temporal and TestCornellBoxGI wire `SceneTLAS`; 1x1 dummy
  textures cover the v210 slots for the control tests.
- Applied in `TemporalResample1/2` (m_curr target and the stream), and in
  spatial `Stream` (both the r_i target and the r_c brdf term).
- `SuppressOutlierReservoirs` port (`w_sum > 25·waveAvg → M=1`) after the
  temporal merge.
- `HLVM_RGI_LOG_FRAMETIME=1` logs ms/frame (real-time gate).

### Proof (Release, RTX 3090, 800×600 half-res trace)

| Config | ms/frame |
|---|---|
| bypass 1 bounce (base) | ~39 |
| full ReSTIR, 1 bounce | ~73 |
| full ReSTIR, 2 bounces | ~60 |
| full ReSTIR, 4 bounces (default) | ~85 |

Static scene M mean=7.71 max=16 (unchanged — visibility is not a regression),
W mean 9.6 (visibility rejects some history), grayscale err 0.091; 0 VUIDs.
The 33 ms target needs the profiling pass (tracer ray cost + ray-query reuse
cost dominate).

## Phase 5a — Real-time pass (v212, 2026-08-22): GBuffer draw caching

### Symptom

Release ~74 ms/frame with the GPU at ~1% utilisation — the frame time was
CPU/API-bound, not GPU-bound.

### Root cause (measured with per-phase CPU timing)

| Phase | Before | After |
|---|---|---|
| GBuffer raster | ~18 ms | ~9 ms |
| RayTrace (FGIPass) | ~4 ms | ~5 ms |
| ReSTIR passes | ~5 ms | ~6 ms |
| Resolve | ~2 ms | ~2 ms |
| Blit/Accumulate | ~2 ms | ~2 ms |
| Total CPU | ~31 ms | ~24 ms |

The GBuffer loop called `NvrhiDevice->createBindingSet` **per mesh per frame**
(24 descriptor allocations/frame) and re-derived each mesh's `FInstanceInfo`
with an O(N²) scene-tree scan. The nvrhi validation layer wrapper added
~18 ms/frame of pure CPU overhead (measured via `HLVM_DISABLE_VALIDATION=1`,
added as an env override; the dev default stays ON).

### Changes

- Per-mesh GBuffer draw cache (FInstanceInfo + binding set), rebuilt lazily
  only when the async albedo texture handle appears. Cleared at shutdown
  (a static cache tripped VUID-vkDestroyDevice-device-05137 at teardown).
- `HLVM_DISABLE_VALIDATION=1` env override for the validation layer wrapper.
- Per-phase CPU timing behind `HLVM_RGI_LOG_FRAMETIME=1` + `HLVM_RGI_NEE=0`
  toggle for profiling.

### Proof (Release, RTX 3090, validation off)

Wall frame time **74 → 46 ms (21.5 fps)**; with 24 accumulated frames the
reservoir M now reaches **24** (mean 8.77), grayscale err 0.080; validator
4/4 PASS on the default (validation-on, Debug) path; 0 VUIDs.

Remaining to 33 ms: the ~20 ms GPU/present side (tracer + reuse ray queries)
needs GPU timer queries — next session.

## Phase 5b — Frame overlap: 33 ms reached (v213, 2026-08-22)

### Symptom

Wall frame ~46 ms despite only ~24 ms of CPU recording and ~18 ms of GPU work
(nvrhi GPU timers added via `HLVM_RGI_GPU_TIMERS=1`): the framework called
`GetDevice()->waitForIdle()` EVERY frame, serializing CPU and GPU.

### Root cause

`DeviceManager.cpp`'s message loop had a per-frame `waitForIdle()` with a TODO
documenting that removing it "allows frame overlap but exposes a real engine
bug: the acquire semaphores are reused before their pending signal completes
(VUID-vkAcquireNextImageKHR-semaphore-01779)".

### Changes

- **Per-acquire-slot event queries** (the "per-index event query" the TODO
  asked for): each acquire slot's completion query is recorded in `Present()`
  (after the frame's render submission), and `BeginFrame` waits on it BEFORE
  reusing the slot's semaphore. Waiting on the render's completion — not just
  the acquire signal — guarantees the semaphore has no pending wait/signal
  operations, which is the actual VUID condition.
- Removed the per-frame `waitForIdle()`; the existing frame-in-flight event
  queue (MAX_FRAMES_IN_FLIGHT=3) provides the pacing.
- GPU timer queries around GBuffer / RayTrace / ReSTIR / Resolve / BlitAccum
  (gated by `HLVM_RGI_GPU_TIMERS=1`).

### Proof (RTX 3090, 800×600, validation ON, default 4-bounce rotating config)

| Metric | Before | After |
|---|---|---|
| Wall frame time | ~46 ms | **~30 ms (≈33 fps)** |
| Acquire VUID 01779 | — (waitForIdle masked it) | **0** |
| Any VUID / validation error | 0 | **0** |
| Reservoir M (32 frames, static) | — | **max 30.0 (the cap), mean 9.16** |
| Validator | 4/4 | 4/4 |

Debug build (validation on): M mean 7.71 max 16, 0 VUIDs, validator 4/4.
