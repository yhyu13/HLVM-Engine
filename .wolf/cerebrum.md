## Key Learnings

- **Project**: HLVM-Engine — UE5-inspired personal game engine, focused on memory management, rendering, telemetry. Linux dev toolchain + C++20. Not focused on rendering/content workflows.
- **NVRHI integration**: Uses forked NVRHI from `https://github.com/yhyu13/NVRHI.git` — never blame NVRHI itself for bugs.
- **ShaderMake**: HLSL → SPIR-V compilation. Config in `Test/<Name>_Data/ShaderMake.cfg`. Entrypoint: `ShaderMake::FindPermutationInBlob()`.
- **Camera convention**: Camera looks in **-Z direction**. For scene at z=-39, camera must be at z > -39. Use `MoveToAndLookAt()`.
- **Depth clear**: `ClearDepthStencilAttachment(cmd, fb, 1.0f, 0u)` NOT `ClearDepthAttachment`.
- **constantBufferOffset**: Defaults to 256 in NVRHI — set explicitly to 0 for GLSL binding 0.
- **FNode transform**: MUST call `UpdateWorldTransform()` after `SetPosition/Rotation/Scale`. Uses dirty-flag `IsUpdating` to prevent recursion.
- **shared_from_this trap**: Only works on `shared_ptr`-owned objects. `std::make_unique` cannot use it.
- **GExecutablePath**: `boost::filesystem::current_path()` — points to CWD, NOT executable dir.
- **MiMalloc2 thread cleanup**: Call `mi::Mallocator::thread_done()` on thread exit.
- **Logging macros**: `HLVM_LOG`, `HLVM_CLOG`, `HLVM_CLOG_ELSE_FATAL`. NOT `HLVM_LOG_F`.
- **Error handling**: No exceptions. Use `HLVM_ASSERT`, `HLVM_ASSERT_F`, `HLVM_ENSURE`, `HLVM_LOG`.
- **Matrix operations**: COPY matrices before comparing. `SetFov()` modifies in-place.
- **CVar system**: `AUTO_CVAR_BOOL`, `AUTO_CVAR_INT`, etc. with flags: `Saved`, `ReadOnly`, `Cheat`, `Console`.
- **CVar INI loading must be explicit**: `CVarManager::CVarManager()` only calls `InitializeDefaultIniPaths()` — it does NOT call `LoadAllFromIni()`. AUTO_CVAR_* globals register at static init, but INI files are never loaded unless some code calls `GetCVarManager().LoadAllFromIni()` after main() starts. Tests that rely on `Engine.ini` overrides must call this in their entry point. Source: bug-052.
- **Public/Private separation**: UE5 pattern — Public/ = header-only interfaces, Private/ = implementation.
- **Include order**: 1) Project headers (Core/, Platform/), 2) Standard lib, 3) Third-party.
- **Deferred shading pipeline**: GBufferFillPass → DeferredLightingPass. GLSL bindings must match FViewConstants/FLightingConstants layout.
- **RT shadows**: Uses TLASBuilder + BLASBuilder. VULKAN RayTracing requires `VK_KHR_ray_tracing_pipeline` + `VK_KHR_ray_query`.
- **Scene loading**: GLTF via Assimp (`AssimpSceneObject`, `Scene3DLoader`). Sponza test scene commonly used.
- **Texture loading**: STB (PNG/JPG) and KTX2 (GPU-compressed) loaders available.
- **KTX1 vs KTX2**: Sponza KTX files are KTX1+ASTC, not KTX2. `supercompressionScheme` is KTX2-only field — reading from KTX1 gives garbage. `ktxTexture2_TranscodeBasis()` only handles Basis formats, not ASTC. PNG/JPG Sponza works via stb_image.

### Verified Vibe_Coding Learnings (2026-05-07)

- **RT Shadow Scale Bug**: `glm::scale(0.01f)` on Sponza in TLAS shrinks geometry to 1% size, causing all rays to miss. Scene bounds become ~(-0.39, 0, -0.39) to (0.39, 0.15, 0). Fix: use `glm::mat4(1.0f)` without scale.
- **Binding 4-Stage Pipeline**: HLSL `register(b0)` → slangc `--bRegShift 256` → SPIR-V `Binding 256` → NVRHI `ConstantBuffer(256)`. All stages must match.
- **Texture_UAV(384) for RT output**: RT shaders use `uRegShift=384` in ShaderMake.cfg, so UAV binding must be `Texture_UAV(384)` in NVRHI layout.
- **ShadowPayload struct required**: TraceRay payload must be a struct (`ShadowPayload`), not `float`. Miss shader receives same struct type.
- **stb_image ThinLTO Issue**: When stb_image is compiled into Runtime static library with ThinLTO, JPEG decoder symbols (`stbi__jpeg_test`, etc.) are stripped. Works when compiled directly into test binary. Fix: Combined approach — (1) `-fno-lto` for STBTextureLoader.cpp preserves JPEG decoder, (2) `-Wl,-allow-multiple-definition` handles stb symbol conflicts with assimp. Both needed orthogonally.
- **Frame Dump Fix (RESOLVED)**: FRenderPassDumper::EndDump() failed with "Two or more immediate command lists cannot be open at the same time" — NOT a NVRHI bug, OUR bug. EndDump() created its own command list while caller had one open. Fix: split into PrepareCopy() (called BEFORE close/execute on caller's cmdlist) + ReadbackAndSave() (called AFTER executeCommandList). The old working approach (commit 1f5c42d) used the SAME command list for copy+close+execute+readback.
- **RGBA16_FLOAT vs RGBA32_FLOAT Crash**: FRenderPassDumper::ReadbackAndSave always interprets data as `float*` (4 bytes/component). If HDRTexture is RGBA16_FLOAT (2 bytes/component), row pitch mismatch causes crash at pixel copy loop. Must use RGBA32_FLOAT to match float* readback.
- **NVRHI Immediate Mode Constraint**: NVRHI immediate mode does NOT support nested immediate command lists. You cannot create a new command list and issue commands while another immediate command list is still open. The fix is to use the SAME command list for all operations (copy + close + execute) OR split into prepare/readback phases.
- **Two-Execute Pattern**: TestSponzaDeferred has GBuffer pass + Lighting pass with separate executeCommandList calls. Frame dump BeginDump must be in SAME pass as EndDump - cannot span two executeCommandList calls.
- **RGBA16_FLOAT vs RGBA32_FLOAT Crash**: FRenderPassDumper::ReadbackAndSave always interprets data as `float*` (4 bytes/component). If HDRTexture is RGBA16_FLOAT (2 bytes/component), row pitch mismatch causes crash at pixel copy loop. Must use RGBA32_FLOAT to match float* readback.
- **Frame Dump Directory**: FImageDump::DumpToPNG fails silently if output directory doesn't exist. Create directory before running with `mkdir -p`.
- **GBuffer/Lighting Shader Mismatch**: TestSponzaDeferred was using GBuffer shaders from TestRTShadowsGBuffer_Data (outputs to SV_TARGET1-4) but its framebuffer uses MRT indices 0-3. Also lighting shader from TestFullDeferredShading2 expected Position at t0 but TestSponzaDeferred provides Diffuse at t0. Fix: Created matched shader set in TestSponzaDeferred_Data/ with GBufferSponzaVS.hlsl (MRT0-3 output), GBufferSponzaPS.hlsl, and SponzaDeferredLighting_cs.hlsl (reads t0-3 matching GBuffer).
- **slangc ignores `#pragma pack_matrix(row_major)`**: HLSL/SPIR-V always uses **column-major** matrix layout regardless of pragma. C++ must upload matrices in column-major order. Use `glm::value_ptr()` which emits GLM's native column-major layout. Manual row-by-row upload (e.g., `view[0][0], view[1][0], view[2][0], view[3][0]`) transposes matrices in shader, breaking view/projection transforms.
- **FVertex struct is 64 bytes, not 44**: `FVertex` uses `glm::aligned_lowp` which makes each `vec3` **16 bytes** (aligned to 16), not 12. Actual offsets: `Position@0, Normal@16, UV@32, Tangent@48`. Input layout MUST use `offsetof(FVertex, ...)` — hardcoded offsets (0, 12, 24, 32) cause vertex attributes to read wrong memory, producing zero/garbage varyings in pixel shader.
- **NVRHI vertex attribute location assignment**: NVRHI's Vulkan backend assigns locations **sequentially** (0, 1, 2, 3...) based on `VertexAttributeDesc` array order in `createInputLayout()`. It does NOT match by semantic name. SPIR-V assigns locations sequentially by VS input struct declaration order. These match ONLY if the array order matches the struct declaration order.
- **slangc optimizes unused varyings away**: If pixel shader doesn't declare/consume a VS output varying, slangc removes it from SPIR-V interface entirely. This can mask location mismatch bugs because the PS won't read the garbled data — but frame dump via compute shader (which reads all GBuffer textures) will reveal the problem.

### Debugging Process Learnings (ReSTIR GI retrospective, 2026-06-06)

- **Isolation first, hypothesis second**: When a multi-stage pipeline produces a wrong image, disable the downstream stages and dump the upstream output. If the post-process (ReSTIR) output is noisy, dump the denoised GI; if that's noisy, dump the raw GI. Don't tweak downstream parameters hoping the input is fine. The ReSTIR iterations spent ~15 turns on merge math before realising the GI shader was the bug.
- **Percentile analysis beats mean/std**: A frame dump with mean ~33/255 and 63% black + 35% at 255 is bimodal — it tells you the pipeline is producing either nothing or saturated output. This is `np.percentile(pixels, [1, 50, 99])` and `np.sum(pixels==0)/N` + `np.sum(pixels>=250)/N`. Mean and std hide bimodality.
- **User's critic is the hypothesis, not background noise**: When the user pastes a critic identifying `SV_HitT` as a 3-component normal, that is the diagnosis — read it first, not last. Don't iterate 15 times and then notice the critic was right.
- **Compacted context ≠ current file state**: A 15-iteration compacted summary can describe "spatial shader has 3×3 merge" when the file on disk is a 34-line passthrough. Always Read the actual source. The harness tracks reads — re-reads are cheap, wrong assumptions are expensive.
- **Debug visualisations must not survive the iteration**: Adding `gOutRadiance = red/green` for `historyValid` and leaving it in the build is a footgun. Use `#ifdef DEBUG_VIS` and turn it off, or remove before the next iteration. The build pipeline will compile your debug output and confuse the next debug session.
- **Tonemap whiplash pattern**: `Reinhard x/(1+x)` → too dark; raw `Exposure=2` → clipping; ACES filmic → correct. Sequence is wrong — the first question should be "is the input HDR legal? what's the max luminance?" If max > 1.0, you need a tonemap before you adjust exposure. Pick ACES first if scene radiance is unbounded.
- **Drop dead bindings**: If `CurrentRadiance`/`HistoryRadiance`/`OutRadiance` are bound to a shader that doesn't read or write them, they are misleading. Either implement the feature (TAA radiance blending) or remove the binding. Don't leave descriptor set slots full of unwired slots — they imply capability that doesn't exist.

Since our DeviceManager uses DebugUtils (not DebugReport), we must use messageIdNumber (VUID number) for filtering, not location.
- [2026-05-16] **Suppress known validation layer false positives rather than refactoring to avoid them** — When Khronos confirms a VUID is a false positive (e.g., #8038), adding it to IgnoredVulkanValidationMessageLocations is the correct engineering decision. Refactoring code architecture (e.g., volatile buffers) just to avoid triggering a layer bug is unnecessary work.
- [2026-06-06] **Don't put `FrameIndex` inside the candidate-position hash in ReSTIR passes** — The candidate *positions* for a static scene should be temporally stable; only the *selection* step should use `FrameIndex`. Putting `FrameIndex` in the position hash makes `y` (selected sample) change per frame on a static scene → per-pixel output reads from a different input pixel each frame → flicker. Standard fix: `hash22(pixel + float2(i * 7, i * 13))` for positions, keep `FrameIndex` only on the RIS selection step. Source: bug-046, `ReSTIR_Generate_cs.hlsl:76`.
- [2026-06-06] **Don't discard the reservoir W weight in spatial reuse "to be stable"** — A common early-ReSTIR shortcut is to compute W then output `gRadiance[y]` unweighted. This is correct for Sponza-style diffuse DI with many SPP samples, but for 1-SPP input it lets a rare bright speckle propagate to 9 spatial neighbors with no calibration. Apply `W` (clamped to [0, 5]) or implement pairwise MIS. Source: bug-046, `ReSTIR_Spatial_cs.hlsl:130`.
- [2026-06-06] **Don't leave a temporal pass's `CurrentRadiance`/`HistoryRadiance`/`OutRadiance` bindings unwired** — If the temporal pass is meant to be "reservoir-only", say so in the shader and remove the binding. If the bindings exist, the shader MUST read them and write `OutRadiance`. Otherwise the temporal pass is dead code that wastes descriptor set slots. Source: bug-046, `ReSTIR_Temporal_cs.hlsl` + `FReSTIRPass.cpp:167-178` bindings.
- [2026-06-06] **Pairwise MIS fixes ReSTIR spatial bias at the source; weighting downstream is a band-aid** — Three-stage progression in TestFewBounceGI: (a) Naive "pick one y, output radiance[y]*W" → 4-frame variance 12.30, snow-flower flicker from outliers propagating uncalibrated. (b) W-applied (clamped [0,5]) → Black% went UP from 6.8 to 9.2 because W was rescaling already-biased samples, not fixing the bias. (c) Pairwise MIS: `out = sum(w_i * radiance_i) / sum(M_i * p_hat_i)`, with position-independent p_hat (luminance) → Jacobian correction = 1.0 and formula is a true weighted blend of all valid spatial neighbors. Result: 4-frame variance 2.08 (-83.1%), Black% 8.5 (back below W-applied), frame-to-frame diff 0.54→0.44→0.28 (temporal pass gets a clean signal). Lesson: fix the algorithm before you polish the visuals. Subsequent features (textures, BRDF, larger radius) compound any pre-existing bias. Source: bug-046, `ReSTIR_Spatial_cs.hlsl` pairwise MIS implementation.
- [2026-06-07] **Don't hardcode cbuffer slot = N+256 for the second buffer** — When bRegShift=256, the second constant buffer must be at slot 256+1=257, not 256+256=512.
- [2026-06-08] **ReBLUR temporal blend: confidence = (FrameIndex-1)/HistoryFadeIn converges to 100% current and throws away history** — Correct form: alpha = max(1/(FrameIndex+1), 1/HistoryFadeIn) — early frames blend more current to avoid stale-history ghosting, later frames settle to steady-state rate. Source: bug-053. Slot 512 is a "natural" looking number but it's wrong — the layout spec just says "buffer N is at slot bRegShift*N", so b0=256, b1=257, b2=258, ... always +1 per buffer. Verified by `TestFewBounceGI.cpp` binding layout: ViewConstants at 512 silently read garbage (the cbuffer was an empty/unrelated slot), causing nonsense view/proj matrices in the GI shader. Commit 2d36716 / bug-050.
- [2026-06-07] **Reuse GBuffer textures for bounce-pass materials instead of per-instance fields** — In the few-bounce GI path, per-instance `info.AlbedoColor` was unset (zero). Bounce hits then sampled zero, making every bounce-lit material look uniform gray. Fix: project the bounce hit through `View*Proj`, get NDC, flip Y (Vulkan convention), then `GBufferDiffuse.Load(int3(pixel, 0))` to reuse the primary pass's textured diffuse. This gives perfect LOD parity between primary and bounce passes and is what the few-bounce path is meant to do anyway. Source: bug-050, `FewBounceGI.hlsl:258`.
- [2026-06-14] **FrameIndex must be part of the GI pixel seed for temporal denoising** — Per-sample/per-bounce seed independence (R0) is necessary but not sufficient. If `pixelSeed` depends only on `(x, y)`, every frame traces identical paths and temporal accumulators (ReBLUR, TAA, etc.) see identical input. The symptom is byte-identical frame dumps even with the denoiser enabled. Fix: add `TemporalFrameCount` to the seed via an unused constant-buffer slot (ViewConstants padding). Source: bug-057, `FewBounceGI.hlsl:142`.
- [2026-06-14] **Denoiser correctness before parameter tuning** — ReBLUR was tuned for ~50 iterations while the real bugs were (1) wrong LH_ZO depth remapping in `ReconstructViewPos`, (2) black fallback in `SpatialBlur`, (3) overwrite of temporal result, and (4) deterministic GI input. After those four fixes the defaults produce stable output; parameter sweeps only matter once the math is correct. Source: bugs R1-R3, bug-057-059.
- [2026-06-14] **Expose denoiser blend factors as CVars** — The spatial/temporal blend alpha should be CVar-driven. Rebuilding shaders for every parameter sweep is process waste. `r_ReBLUR_SpatialAlpha` now exists and maps through `FReBLURConstants` without shader recompilation.

### FBindingLayoutBuilder (DONE)
- **Location**: `Engine/Source/Runtime/Public/Renderer/Common/FBindingLayoutBuilder.h`
- **Purpose**: Eliminates manual Vulkan binding math errors. Accepts logical HLSL register indices (b0, t1, s2) and computes SPIR-V binding automatically using ShaderMake shift constants (t=0, s=128, b=256, u=384).
- **Key API**: `AddConstantBuffer(0)` → binding 256, `AddTextureSRV(0)` → binding 0, `AddSampler(0)` → binding 128.
- **Companion**: `FBindingSetBuilder` mirrors the layout builder for constructing `BindingSetDesc` with the same shift math.
- **Test**: `TestBindingLayoutBuilder` — 5 test cases, all passing.
- **Lesson**: FString `operator*()` returns `const char8_t*`, but FString implicitly converts to `const char*` via `operator const char*()`. NVRHI APIs expect `const char*` — pass the FString directly, don't dereference it.

### FRayTracingPipeline (DONE)
- **Location**: `Engine/Source/Runtime/Public/Renderer/RayTracing/FRayTracingPipeline.h`
- **Purpose**: Encapsulates RT pipeline boilerplate — shader loading, binding layout, pipeline creation, shader table management, dispatch.
- **Key API**:
  - `InitializeFromLibrary(Device, ShaderLib, "RayGen", "ClosestHit", "Miss", "ShadowMiss")`
  - `CreateBindingLayout().AddConstantBuffer(0).AddRayTracingAccelStruct(0)`
  - `FinalizePipeline(MaxPayloadSize, MaxAttributeSize)`
  - `BuildShaderTable()`
  - `DispatchRays(CmdList, Width, Height)`
- **Lesson**: `nvrhi::rt::State` only has `setShaderTable()` and `addBindingSet()` — there is NO `setPipeline()`. The pipeline is bound implicitly via the shader table.
- **Lesson**: `nvrhi::rt::PipelineHitGroupDesc` uses fluent setters (`setExportName()`, `setClosestHitShader()`) — cannot use braced initializer list.
